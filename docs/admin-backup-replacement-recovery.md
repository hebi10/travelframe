# 관리자 백업 슬롯 교체: 진행 상태 및 재시도

관리자 슬롯 교체는 현재 기본 비활성입니다. FUNCTIONS_ENABLE_ADMIN_BACKUP_DELETION 설정을 true로 변경하지 않습니다.

- 교체 시작 전 다른 관리자 작업/기존 프로젝트에 예약된 업로드를 확인하고 거부합니다.
- 서버 트랜잭션에서 슬롯을 replacing으로 표시하고 새 projectId를 pendingProjectId에 기록합니다.
- 해당 슬롯의 신규 업로드를 차단합니다. 이후 기존 프로젝트의 Storage/Firestore 데이터를 삭제하고, 새 프로젝트 슬롯으로 전환합니다.
- 중간 삭제 실패 시 replacing 상태가 남습니다. 같은 이전·새 프로젝트로 요청을 재시도하면 남은 삭제와 최종 전환을 다시 시도할 수 있습니다. 누락 Storage 파일(404)은 삭제된 것으로 처리됩니다.
- 다른 새 프로젝트로의 중복 변경 요청은 거절합니다.

**중요:** 이는 roll-forward(삭제 작업 재개)로, 이미 삭제된 파일을 복원하는 rollback이 아닙니다. 일반 사용자 슬롯 변경/기존 업로드 완료 경합 등은 여전히 실기기·Emulator 검증이 필요합니다. 승인·백업·실패 주입 테스트 전까지 PR Draft 및 운영 비활성 상태 유지.
