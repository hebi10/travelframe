# 보안 보완 운영 반영

## 로컬 변경

- 보관함에 영구 소유 UID를 저장하고 다른 계정/로그아웃 상태에서는 기록 화면을 잠근다. 기존 무소유 자료는 명시 확인 후 연결하며 삭제하지 않는다. 기기당 하나의 보관함만 지원한다.
- 구독 조회가 늦게 반환되어도 이전 계정 결과를 현재 계정에 적용하지 않는다.
- 새 앱은 Firebase Storage 미디어의 장기 토큰 URL을 사용하지 않는다. URL에서 토큰을 제거하고 본인 버킷/UID 경로 검증 및 Firebase ID 토큰 인증 후 로컬 캐시로 표시한다.
- `completeBackupUpload`, `completeMusicUpload`에 `privateDownload:true`를 전달한다. 서버는 소유권/예약/크기/MIME/객체 세대 검증 후 새 업로드의 다운로드 토큰을 폐기한다. 구버전 요청 및 이미 완료된 기존 업로드는 유지한다.
- 구매 검증: UID당 60초에 20회 공급자 조회, 동일 토큰 동시 호출 방지, 활성 구매 15초 캐시. RTDN은 캐시/제한을 우회해 환불·취소를 새로 검증한다.

## 반영 순서

1. 서버 코드 및 보안 규칙 검증 후 Functions를 배포한다. 로컬 변경만으로 운영 방어가 적용되지는 않는다.
2. 내부 테스트에 새 Android 앱을 배포하여 신규/기존 사진 표시, 원본 복원, 영상 재생, 음악 재생, 로그아웃/다른 계정 로그인, 구매/환불을 확인한다. 새 private 파일은 구버전 앱에서 표시되지 않을 수 있으므로 새 앱 업데이트가 필요하다.
3. 새 업로드의 metadata에 다운로드 토큰이 없고, 인증 없는 다운로드는 거절되며 소유 계정만 읽을 수 있는지 운영 테스트 파일로 확인한다.
4. 새 앱 전환이 확인된 뒤 기존 업로드 토큰 폐기 범위와 복구 계획을 확정한다. 이번 작업에서는 기존 링크를 일괄 폐기하지 않는다. 따라서 이미 알려진 기존 링크의 접근 가능성은 남아 있다.
5. App Check는 Android Play Integrity 등록·클라이언트 토큰 발급·실기기 검증 및 서버 모니터링을 먼저 진행하고 강제 적용한다. 클라이언트 준비 없이 `FUNCTIONS_ENFORCE_APP_CHECK=true`로 바꾸면 정상 사용자도 차단된다. 이번 변경에서 강제 적용하지 않았다.

## 남은 제한

- 백업은 종단간 암호화가 아니다. 운영 관리자 권한으로 읽을 수 있다.
- 로그인 계정 소유권 검사는 정상 앱 내 계정 혼합을 막는다. 루팅/탈옥·앱 저장소 직접 변조까지 방어하는 암호화 기능은 아니다.
- 기존 보관함의 소유 계정 분실 시 임의 강제 변경은 지원하지 않는다. 계정 복구가 필요하다.
- npm audit의 중간 등급 3건은 Expo Router의 query-string/decode-uri-component 전이 경로에 남아 있다. 호환되지 않는 메이저 변경은 적용하지 않았다.
- Google Drive 공유 권한은 이전 감사에서 소유자만 접근하도록 확인했으며 변경하지 않았다. 앱 백업 저장소는 Google Drive가 아닌 Firebase Storage다.
