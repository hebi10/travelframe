# TF-ADS-01 — 보상형 광고 기반 내보내기

## 현행 동작과 범위

- 무료 로그인 사용자는 영상 만들기, 레거시 영상·이미지 저장 및 공유를 실행할 때 광고 시청을 선택한다. 보상 획득이 확인되면 해당 작업을 진행한다.
- Pro·Plus·Expert 및 과거 `ad_remove` 영구 구매자는 광고 없이 실행한다. 비로그인은 기존 광고 정책을 유지한다.
- 사진 원본, 기록, 촬영, 삭제·복구·백업, 구독 상품 및 서버 권한은 변경하지 않는다.
- 기존 저장 *후* 전면 광고를 이 출력 경로에서 제거해 한 번의 출력에 두 개의 광고가 나오지 않도록 한다.
- 광고 길이는 SDK의 광고 크리에이티브에 따라 달라지며 30초를 강제하거나 보장할 수 없다.
- 명시적 동의 `광고 보기`, 보상 콜백 확인, 조기 종료 시 출력 차단. 광고 SDK/네트워크/동의 문제 또는 운영 광고 단위가 없는 경우 기존 오프라인 출력은 허용한다.
- 광고 요청에 동의하지 않아도 앱 내 편집과 기존 콘텐츠 접근은 가능하다. 권한 검증이 완료되기 전, UMP 광고 요청 허용 전에는 광고를 요청하지 않는다.

## AdMob 운영 준비

1. Android 앱 `com.haebi.photoguide`에 *보상형* 광고 단위를 새로 생성한다. 기존 `/5093683221`은 전면 광고 단위이므로 재사용하지 않는다.
2. 승인된 광고 단위 ID를 `app.json`의 `expo.extra.admob.androidRewardedAdUnitId`에 추가한다. 이 변경 전 프로덕션 빌드는 새 광고를 요청하지 않는다.
3. 개발 빌드는 Google 공식 보상형 **테스트 단위**만 사용한다. 광고 단위/실제 노출/AdMob 계정 상태는 코드로 확인할 수 없다.
4. 테스트 환경에서 무료·광고 제거 영구권·Pro/Plus/Expert, 광고 로딩 실패·거절·취소·미완료, UMP, 저장 실패, 앱 백그라운드·화면 이동, MP4·이미지 내용과 워터마크를 확인한다.
5. 승인형 CI, 서명 AAB, Google Play 내부 테스트 게시를 각각 별도 단계에서 수행한다. 이 기능의 PR만으로 자동 배포하지 않는다.

## 별도 확인 사항

- 영상 렌더링 캔버스의 `showWatermark` 조건은 구현되어 있으나 저장 MP4의 픽셀·워터마크는 Android 실기기 확인이 필요하다.
- 레거시 이미지 출력은 기존 `saveImageToLibrary` 경로로 저장되며, 사진 파일 자체에 워터마크를 합성하는 로직은 별개이다.
