# TF-CAPTURE-01/02 — 촬영 직후 선택형 수치 기록

## 기준
- 2026-11-18 확정된 TravelFrame 프로젝트별 저장·촬영 기록 통합 기획
- 선행: TF-CLOUD-08 PR #184 (현재 main 미병합); 이번 변경은 해당 브랜치를 기반으로 별도 PR
- Android 앱 촬영 화면에만 적용. 이미지 가져오기·영상 편집·기존 사진 원본은 변경하지 않는다.

## 구현
- `CameraScreen`의 실제 `saveCapturedPhoto`가 앱 보관함에 저장을 성공한 직후 고유 `PhotoItem.id`로 `onPhotoSaved`를 호출. 기기 앨범 권한·클라우드 업로드보다 먼저 알림을 전달한다.
- `BodyFrameCameraScreen`은 `photo.projectId`, `photo.id`로 프로젝트 설정 및 기존 수치 기록을 읽고, `enabled && promptAfterCapture` 조건에서 모달을 연다. `sequence`로 사진을 재검색하지 않는다.
- 빠른 연속 촬영은 FIFO 대기열로 한 장당 한 번씩 처리. 다른 프로젝트로 전환되어도 저장 당시의 photoId/projectId 및 프로젝트 이름·시각·순서·사진을 보존한다.
- `BodyMeasurementEditorSheet`를 촬영 모드에서도 재사용한다. 사진 썸네일·프로젝트명·촬영 순서·날짜를 보여주며 프로젝트별 선택 항목(몸무게/체지방률/골격근량/허리둘레)과 메모를 편집할 수 있다.
- `정보 저장`/ `나중에 입력`/ 닫기/Android 뒤로 가기. 비어 있으면 데이터 기록 없이 닫기. 건너뛰거나 모달이 닫혀도 기존 사진은 유지된다.
- 숫자 범위 검증은 기존 `parseMeasurementInput`을 유지한다. 저장 오류는 사용자 입력을 유지한 채 화면에 표시하며 같은 모달에서 재시도한다. 저장 중 중복 탭은 ref 잠금으로 방지한다.
- `saveBodyMeasurement`는 동일한 `projectId + photoId + manual` 조합을 같은 항목에 덮어써서 재시도/중복 호출로 새 수치 레코드가 늘어나지 않는다. Health Connect 원본은 자동 수정하지 않는다.
- 신규 프로젝트 두 진입점(카메라·기록)은 새 프로젝트에 한해서 `enabled=true,promptAfterCapture=true` 및 몸무게 1개 기본으로 초기화한다. 기존 프로젝트의 설정 및 사용 중지 상태는 바꾸지 않는다.
- `나중에 입력` 시 사진 상세에서 기존 수치 기록 입력/수정을 계속 지원한다. 자동 팝업은 화면 생명주기 동안 보유하며 앱 프로세스 종료 후의 입력 내용 복원까지 보장하지는 않는다.
- 기타 민감 정보의 Firebase 전송은 추가하지 않는다. 관련 백업·복원은 TF-CLOUD-01 범위이다.

## QA 승인 조건
- 새 프로젝트 생성 시 기본 팝업, 기존 프로젝트·설정 끔 시 팝업 없음
- 고유 photoId 기준 순서 보존 및 프로젝트 A/B 혼선 없음, 빠른 촬영 N장 대기열 처리
- 앱 저장 실패에서는 팝업 미노출, 앨범 권한/클라우드 실패에서도 앱 사진과 입력 가능
- 모두 비운 값/나중에 입력은 기록 미생성; 몸무게만/메모만/다중 항목 정상 저장
- 비정상 숫자 입력은 저장 차단, 저장 공간 오류·비동기 실패 시 값 보존 및 재시도
- 같은 사진에 대한 반복 저장은 데이터 중복 없음, Health Connect 기록 자동 변경 없음
- 재진입 시 사진 상세 수정, Android 뒤로/탭 이동/앱 백그라운드와 큰 글씨·폴더블의 바텀시트 검증
- 관련 Node 테스트, TypeScript/Lint/Android 빌드/Firebase 정책 CI. 실기기 QA는 별도.

## 배포 안전성
이 PR은 코드 및 CI 검증용이며 `main` 병합, Firebase 운영 배포, Google Play 내부/비공개 업로드 및 정식 출시는 별도 승인이다.
