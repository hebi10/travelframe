# Body Frame 사진 파일 식별자 안전성

## 기존 위험

프로젝트의 사진/미리보기 파일을 표시 순서인 `sequence` 기반 파일명(`001.jpg` 등)으로 저장했습니다. 순서 정렬은 메타데이터만 변경하므로, 사진 삭제 뒤 재사용된 순서 번호의 저장 파일이 다른 원본과 충돌할 수 있습니다.

## 변경

- 신규 저장의 파일명을 불변 사진 ID 기반 `photo-<photoId>.jpg`로 변경했습니다. 화면 표시 번호와 저장 파일명은 독립적으로 유지합니다.
- 동일 경로에 다른 내용이 이미 있다면 기존 파일을 삭제하지 않고 오류를 반환합니다. MD5가 동일한 경우에만 재시도를 허용합니다.
- 기존 `001.jpg` 등 파일과 URI는 업데이트만으로 이동/삭제하지 않습니다. 기존 Stage 2 미마이그레이션 사진은 ID 경로로 복사한 뒤 메타데이터 저장이 완료되어야 원본을 정리합니다.

## 검증 및 출시 조건

- `tests/body-frame-photo-identity-storage.test.mjs`에서 ID 경로 독립성, 기존 원본 보호, 경로 충돌 방지, 레거시 마이그레이션을 검사합니다.
- CI에서 TypeScript/lint/전체 테스트/Android 빌드 검증을 재실행해야 합니다.
- 기존 버전에서 만든 여러 사진이 있는 실기기에 업데이트한 뒤 **순서 변경 → 중간 사진 삭제 → 재촬영 → 영상 제작 → 백업/복원**을 검사합니다.
- 원본 기기 기록은 QA 완료 전까지 삭제하지 않습니다. 운영 배포나 실기기 QA를 완료한 것으로 표시하지 않습니다.
