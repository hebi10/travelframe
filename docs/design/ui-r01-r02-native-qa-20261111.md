# TravelFrame UI-R01·UI-R02 — 전후 비교·촬영 Android QA

기준: 2026-11-11 / main 9e6d84cad89b59ae34f0fe45b6117b843de731e9 / com.haebi.photoguide

## 1. 수행 목적과 범위

기존 PR #149로 수정된 사진 비교 터치 분기와 현재 구현된 촬영·기준 사진 UI의 동작을 최신 앱 코드 기준으로 검증한다. 실제 앱 런타임 소스·기능·가격·Firebase·사진 라이브러리·Google Play 배포는 수정하지 않는다. QA 전용 Python, Node 테스트, GitHub Actions와 문서만 추가한다.

Android 캡처의 앱 UI는 실제 에뮬레이터 실행 화면이고, 인물 사진은 비실제 합성 데모다. Android 에뮬레이터 검사는 물리 ARM64 기기의 카메라 센서/저장/손가락 조작과 구분해야 한다.

## 2. UI-R01 — 전후 비교 좌우·상하 스와이프

- 대상: BodyFrameCompareScreen / comparison-pan-gesture의 현행 구현, 수정 아닌 실제 동작 검수.
- 대상 기기 규격: phone-412dp, tablet-600dp, dark/light 100%. 4개 프로필/테마 셀.
- Android 실제 입력: adb input swipe로 사진 위에 위쪽 세로 이동·세로 우세 대각선·좌/우 가로 이동을 전달.
- 검증: native UI XML의 SeekBar 접근성 표시 퍼센트와 화면 좌표를 비교. 세로 스와이프에서 부모 ScrollView 위치가 이동하고 비교 퍼센트는 유지되어야 한다. 가로 스와이프에서는 퍼센트가 변해야 한다.
- 추가: 25/50/75% 프리셋 버튼, 나란히·겹쳐보기 화면, A/B 선택 시트 열기·닫기, 사진 원본 ID 불변.
- 증거: 각 동작 시작/종료 좌표·입력 밀리초·전후 접근성 값, 실제 Android PNG/XML/JSON과 SHA-256.
- 한계: 실사용 손가락·TalkBack 음성 순서·150% 글꼴·폴더블 전 조합은 UI-R08 및 기기별 확인 대상이다.

## 3. UI-R02 — 촬영·기준 사진·권한 상태

- Android API35 에뮬레이터 phone-412dp, tablet-600dp, dark/light 100%에서 총 36개 UI 캡처 목표.
- 화면: 촬영, 기준 사진 위치/투명도, 촬영 설정, 저장 대상, 가이드, 색감, 확대, 조명 및 카메라 권한 거절.
- 촬영 버튼·프로젝트 선택 버튼의 실제 터치 영역, 기준 사진 투명도 SeekBar와 확인 버튼, 접근 가능한 하단 패널, 권한 복원 버튼 확인.
- Android 네이티브 카메라 권한 거절/복원과 원본 QA 사진 ID 불변 검증. 한 장이라도 캡처 오류나 검증 누락 시 FAIL로 보고한다.
- 에뮬레이터 카메라 화면의 "사용할 수 있는 카메라를 찾는 중" 표시는 카메라 센서 비검증 상태로 분류한다. 정상 촬영/줌/토치 사용을 성공으로 보고하지 않는다.
- 실제 후면 센서 프리뷰, 실물 줌/손전등, MediaStore/앱 보관함 저장, 진짜 JPEG 사진/EXIF, 실제 프레임·화면 회전은 물리 ARM64 기기의 후속 시험이 필요하다.

## 4. UI-R02 — ARM64 실기기 QA 체크리스트 (별도 PASS 필수)

1. 테스트 전용 사진과 분리된 계정, 기기 모델·Android 버전·APK 또는 테스트 배포 코드·서명/커밋을 기록.
2. 카메라 권한 거절 → 안내 → 허용 → 실제 정상 프리뷰 확인. 검은 화면/카메라 검색 중 상태의 원인 기록.
3. 프레임 가이드·기준 사진 위치·크기·투명도 25/50/75%와 촬영 패널 열기·닫기·위아래 스크롤, 마지막 상태 유지 검증.
4. 기기에서 지원하는 줌 비율과 실제 토치 LED 동작, 전면/후면 전환·회전·Safe Area 확인.
5. 테스트 사진 3장 촬영·원본/미리보기·파일 명칭·촬영 날짜·프로젝트 순번·MediaStore 보관 옵션 확인.
6. 앱 홈 복귀 및 재시작 후 조건 복원, 저장 권한 거절/오류·백그라운드 상태 회귀 검증.
7. 실제 카메라 결과 PNG, 동작 기록, 권한/파일 보존 QA를 Drive에 보관하고 PASS/FAIL로 확정. 데이터·동작이 관측되지 않았다면 완료 판정 금지.

## 5. 실행 게이트와 후속

- GitHub PR 브랜치 qa/ui-r01-r02-gesture-camera-20261111에서 한 번 빌드한 QA APK를 재사용해 R01/R02 Android 테스트를 순차 수행한다.
- 한쪽이 실패하더라도 다른 쪽의 결과를 기록하고, 각 원본 PNG·XML·JSON의 해시와 APK·소스 SHA를 독립 검증한다.
- 전체 Quality·Secret Scan·Android QA·원본 readback 통과 전 main 병합 금지. Play/프로덕션 배포는 절대 자동 실행하지 않는다.
- UI-R01은 동적 제스처 실제 증거가 PASS일 때 완료.
- UI-R02는 에뮬레이터 UI PASS와 ARM64 실제 카메라 PENDING을 구분해 보고. 실기기 미완료면 R02 전체 완료 선언 금지.
- 후속 UI-R03 기록·프로젝트 목록과 상세의 사진/진행률/행동 우선순위 개선, UI-R04 수치 기록, UI-R05 영상, UI-R06~08 공통 마감·24개 환경 검증 및 STORE-03-C/D 실제 화면 기반 설명 이미지 제작·Play 등록.
