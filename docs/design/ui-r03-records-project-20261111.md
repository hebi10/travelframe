## 2. 기록 목록 (S03)

1. 최신 또는 지정된 프로젝트 대표 사진 선택(`coverPhotoId`, sequence), 프로젝트 식별자와 눌러서 열기 동작은 그대로 유지.
2. `cover.previewUri ?? cover.uri` 이미지를 `contain`으로 표시해 3:4 대표 프레임에서 인체 사진이 임의로 잘리지 않게 변경.
3. 사진 기록 수·목표·진행률을 동일한 핵심 정보 묶음에 배치, 그래픽 진행률 바로 아래에 변화 영상 길이를 보조 정보로 배치.
4. 사진 수·목표 수·진행률을 프로젝트 카드의 접근성 안내에도 포함.
5. 프로젝트 0개 빈 상태, 1개, 다수 프로젝트와 보관·복원, 생성 제한, 새 프로젝트/바로 촬영 버튼 유지.
6. 반응형: 콘텐츠 너비 560dp 미만은 1열, 이상은 2열. 카드 대표 이미지 108~128dp 유지.

## 3. 프로젝트 상세 (S04)

1. `기록/수치/통계` 세 탭과 상단 설정/뒤로 가기 유지. 순서 변경 중 탭 잠금 유지.
2. 전후 비교 카드: 시작·최근 사진의 고정 2장 프리뷰를 **72×110dp**로 축소하고, 사진 2장 이상일 때 기존 비교 화면 이동 유지. `contain`으로 원본 비율 보존.
3. 사진 0~1장은 짧은 상태 문구만 표시하여 미사용 기능 영역을 압축.
4. 기록 수·목표 수에 '장' 단위를 명시하고 진행률·오늘 사진 찍기·기록 그리드의 세로 간격을 축소하여 기록 접근성을 높임.
5. 사진 추가, 순서 조정(길게 누르기·순번 이동), 촬영, 변화 영상 만들기, 수치·통계·알림, 프로젝트 설정 기능과 데이터 모델 보존.

## 4. 회귀·시각 QA 조건

- 자동 테스트: `tests/ui-r03-records-project.test.mjs`로 TSX 구문, 커버 비크롭, 진행률/상세 카드 밀도, 3탭·원본 사진·앨범 추가·재정렬·프로젝트 복원을 검증. 기존 Stage 10·14 테스트 유지 및 필요한 수치 기준 갱신.
- Android CI: `body-frame-device-qa.yml`에서 `ui/ui-r03-*` 브랜치를 Stage13 진짜 Android 캡처 4개 화면 폭(360·412·600·750dp)에 포함. 라이트·다크, 100·130·150% 기존 매트릭스와 원본 PNG/XML/JSON/아티팩트 확보, 통합 검증 후 PASS 판단.
- 별도 기준선: 선행 PR #150의 프로젝트 0/1/3개와 사진 0/1/12장 QA 결과와 비교. 선행 PR 실패/미병합 상태에서는 `UI-R03`의 해당 상태가 검증됐다고 주장하지 않음.
- 실기기 필수: 360dp 150% 긴 이름/버튼 줄바꿈, 600·750dp 2열 카드, 실제 인체 사진 원본 fit, TalkBack 순서, 사진 순서 드래그/저장.

## 5. 병합 및 배포 게이트

1. TypeScript·ESLint·Node 회귀 테스트·Firebase Rules·Functions·Android Gradle/Manifest·Secret Scan 모두 GREEN.
2. Android 실제 캡처 4개 규격 성공, 시스템 Pixel Launcher ANR 등의 외부 오류는 별도 실패로 유지. 화면 기록 또는 원본 검증이 실패했다면 병합 보류.
3. PR #150/#151의 QA-only 변경과 충돌하지 않는지 재확인하고 통과 후에만 `main` 순차 병합.
4. 이번 변경은 Firebase 운영, Google Play AAB/이미지 게시, 결제/광고/Health Connect, 실사용자 사진·로컬 저장 구조를 건드리지 않음.
