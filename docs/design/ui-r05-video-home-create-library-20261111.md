## 2. 화면별 구현

### 영상 홈
- 기본 영상 만들기 CTA는 유지. 저장한 영상이 있는 경우 저장 목록을 광고/플랜 안내와 프로젝트 목록보다 위에 표시.
- 저장한 영상 섹션에 총 개수 추가. 최근 영상 3개의 커버를 72×92dp로 확대하고 생성일, 길이, 출력 비율을 분리해 표시. 카드에서 재생/상세 화면으로 이동하며 접근성 설명에는 제목/날짜/길이가 포함됨.
- 저장 영상이 없으면 프로젝트 선택 목록 다음에 기존 빈 상태 안내. 비로그인 주간 1회 출력 안내·프로젝트별 만들기·저장 영상 전체 보기와 권한·정책 유지.

### 영상 만들기
- 기존 3:4 기준 미리보기 폭: 화면 82%, 최대 360dp, 화면 높이·출력 비율에 따른 0.30 계수와 원본 `TripClipRecordingCanvas` 유지.
- 미리보기 헤더에 선택 사진 수·총 길이·선택한 출력 화면 비율을 동시에 표기. 미리보기 접근성 설명을 추가하고 선택 비율이 곧바로 표시되는지 확인.
- 영상 설정 제목 옆에 `화질p · 비율`을 요약. 옵션 카드 좌우 패딩/행 간격만 축소하고 기존 여섯 행(사진 수, 사진 간격, 영상 길이, 화질, 화면 비율, 텍스트)을 보존. 영상 만들기 고정 푸터·진행률·취소·앨범 저장 재시도 및 플랜/게스트 한도 동작 그대로 유지.
- 길게 반복되는 사진 순서 안내를 단축하되 사진 정렬과 생성에 이용되는 `sequence`는 건드리지 않음.

### 영상 보관함
- 저장된 영상 제목은 최대 2줄, 커버 84×108dp, 재생/상세 액션 명확화. 생성일과 영상 길이·비율을 각각 라벨로 구분.
- `/video/[id]` 이동, 기존 비디오 플레이어, 삭제 확인 다이얼로그·저장 파일 삭제·빈 상태·다시 만들기 기능 유지. 모든 버튼 44dp 이상.

## 3. 자동 QA
- `tests/ui-r05-video-screens.test.mjs`: TSX 파싱, 디자인/접근성, 기존 프로젝트·영상 경로·앨범 저장·취소·한도/백업 정책 보존.
- Android Stage13 실제 캡처: API35 × 360/412/600/750dp × 다크/라이트 × 시스템 글꼴 100/130/150%, 총 기본 24 환경. `ui-r05-visual-verify`가 PNG/XML/해시/픽셀/정보 상태를 C7 검증기로 독립 확인. **Stage13의 영상 보관함은 빈 데모 데이터일 수 있음**.
- `ui-r05-native-video`: 412dp **별도 폐기형 오프라인 에뮬레이터**에서 기존 `capture-android-qa.py`의 실제 MP4/실패/백그라운드 취소 QA 함수를 활용. 합성 사진 3장·원본 손상/누락·취소의 부작용 방지, 0.3초 1080×1440/9프레임 H.264, 로컬 보관함과 앨범 저장 결과, 등록된 영상 상세 화면 및 디코딩한 프레임을 근거로 검증.
- `ui-r05-native-verify`: **별도 job**에서 원본 MP4 H.264/길이/프레임/해시를 ffprobe로 재확인하고 캡처 PNG/XML/JSON과 APK 해시·저장 데이터·게스트 쿼터를 검사. 실패/취소 상태가 모두 정확히 한 번 기록되었는지 확인.
- 실제 재생 화면의 원본 캡처는 검증할 수 있어도 물리 ARM64 기기의 정상 재생·음악/오디오/OS 앨범 재생 동작은 **별도 PENDING**. 인코더 QA와 실제 사용자 사진·TalkBack·Play 배포를 동일한 PASS로 주장하지 않음.
