## 기능 QA와 남는 차이
기본9개 표면의 보정 후 원본은 final/, 같은 너비 비교는 comparison-final/이다. 사진 가이드 noncompact dark 분기를 보정해 실제 트랙/값/손잡이의 밝은 대비를 확인했다. 프로젝트 헤더의 실제 bounds는 [184,163][896,289]로126px=48dp이며 변경 전227px≈86.5dp에서101px 줄었다. 확대/조명 닫기는 각각116×116px≈44dp이다.

5556의 신규 QA 환경에서 노출값을 변경하는 VisionCamera prop의 unhandled 취소 예외를 발견하여 별도 수명관리 드라이버와 실행형 회귀로 보정했다. prop/getInitialExposureBias를 제거하고 현재 onStarted 세션에서만 적용하며 중지·교체된 작업의 취소만 처리한다. 현재 요청 실패·일반 오류는 안내로 전달한다.

독립 리뷰에서 최대100배 장치의1x가 정수퍼센트 저장으로1.495배가 되는 기존 정밀도 문제도 발견했다. 공통 normalizeCameraZoomPercent를 소수4자리로 바꾸고 모델/전역설정/프로젝트컨텍스트/핀치에 일관되게 적용했다. 실제 JSON 저장·재복원과 최대1000배의 오차≤0.001배를 실행형 테스트로 확인했다. 저장키·버전·기존 정수값·플랜 정책은 유지한다.

기존5554에는 seed/권한변경/촬영/미디어삭제를 수행하지 않았다. user-data-preservation.json은 현재 프로젝트1개·사진2장·영상1개(0.2초)의 메타데이터와 실제 파일 해시/읽기 성공을 기록한다. 작업 전 전체 파일 해시를 새로 채취하지 않았으므로 이 기록을 작업 전후 해시 동일성 증거로 확대하지 않는다.

최종 공식 기본 테스트362파일·typecheck·lint·diff --check가 통과했다. 마지막 Tap 터치영역 보정은 별도 실제 컴포넌트 회귀7/7로도 확인했다. Windows Kotlin CLI 테스트는 설치된 JDK21/Kotlin compiler를 프로세스 한정 매핑해 실제 컴파일/실행했다. 검증 로그는 D:/dev_app/.setup/camera-ui-v2-final-*이며 제품 테스트 코드를 건너뛰지 않았다. verification.json과 source-manifest.json에 코드·검증 식별 정보를 보관한다. Firebase Rules 별도 환경은 미실행이다.

360dp/150%의 새 프로젝트 직접입력 IME에서 고정 CTA45px 일부가 가려짐을 실제 이미지로 발견했다(qa-runtime/14-project-custom-ime-360-150.png). Activity 기반 IME 이벤트 screenY549dp와 실제 Modal 캡처의 키보드상단505dp 사이44dp 차이를 계측했다. 생성 모달 KAV에 Android top inset offset52dp만 적용한 뒤 숫자/문자 키보드 모두에서 입력·취소·생성·닫기의 전체 노출을 확인했다(118/122 PNG). 100% 복원 환경의 숫자 입력·고정 CTA 회귀도 통과했다(212 PNG).

가이드 숫자 직접입력도 360dp/150%에서 가로 bounds가 음수가 되어 접근할 수 없는 결함을 발견했다(65-guide-top-360-150.png). 원인은 compact slider의 width100%/flex0가 가로행 전체를 차지하는 구조였다. GuideSizeSlider만 flex1/minWidth0 wrapper에 넣어 기존58dp 입력칸을 확보했다. 100% 실제 bounds [847,1686][1000,1803]로 정상화했고 150%에서도 실제 숫자 입력50·포커스·44dp 닫기·IME 노가림을 QA가 확인했다(84-guide-number-ime-fixed-360-150.png). 숫자입력·슬라이더·commit 저장 정책은 유지한다.

슬라이더 위 수직스와이프에서 화면이 스크롤되지 않고44→49%로 변하는 기존 결함도 재현했다(65/71 및91a/91b PNG). SmoothValueSlider만 수평Pan 활성화/수직fail, 별도Tap과 같은 확장 터치영역으로 보정했다. 인식 전에는 값 변경/저장0회, 인식된 드래그는 손가락을 정확히 따라가며 취소 시 마지막 표시값을 저장하는 기존 정책을 유지한다. 색감 실제 QA에서 세로swipe 값0 유지+본문232px 스크롤, 가로drag+40·Tap+20·슬롯2저장/초기화/재선택복원에 성공했다(129/132/136/139/141 PNG). 사진 버튼의 가로패딩만 줄여150% ‘초기화’의 어색한 음절 줄바꿈도 보정했다. 최종 큰 글씨 캡처에 결과를 기록한다.

### 최종 네이티브 확인
별도 [QA 보고서](D:/dev_app/travelframe/docs/design/camera-ui-v2/qa-runtime/summary.md)에 각 실행과 PNG/XML/JSON·미검증 범위를 연결했다. 360dp/150% 프로젝트·촬영설정·가이드·사진·색감·확대·조명,420dpi/100% 입력·백그라운드·권한 거절/재허용을 대표 시나리오로 확인했다. 사진 표시 제거 뒤에도 QA 사진2장 해시가 같았고, 타이머 실제 countdown7에서 기록 탭 이탈 후11초가 지나도 사진2장이 유지됐다. 확대3.0x·선택1개·닫기/재진입 유지, 후면 조명 선택 유지·전면 비활성 안내도 통과했다.

최종 신규 QA 기기는420dpi/100%·후면·1x·조명/타이머끔·촬영메인으로 복원했다. 관련 오류가 관찰되지 않은 로그와 원본2장 해시를 보관한 뒤 신규5556만 종료했다. AVD 파일과 QA 데이터는 삭제하지 않았으며 기존5554와 Metro8081은 실행 상태로 유지했다. 기존5554의 프로젝트/사진2장/영상0.2초는 재실행 뒤 ID와 파일SHA도 모니터링 기준과 같았다.

실기기·모든 설정값 조합·라이트테마/태블릿 전체24조합·TalkBack·클라우드/계정/결제·저장장치 장애·배포APK/Play 검증은 이번 대표 네이티브 QA 결과에 포함하지 않는다.

### 남는 표현 차이
- 생성 main 시안은 동일너비1080에서 높이2558, 실제2424로134px 차이. 강제 세로 늘임 없이 비교하고 실제 Android 시스템 safe area를 유지했다.
- main-header.png는 종횡비 차이를 배제한 헤더 컴포넌트1:1 비교본이다. 전체화면 같은너비1080 기준의 생성 헤더와 XML로 구한 네이티브 헤더를 잘라 같은캔버스에 정렬했다(네이티브 픽셀 무변경). 생성 헤더는 약42.4dp, 실제는 설계기준48dp이며 터치/글자여유를 위해 실제48dp를 유지한다. 상세 crop/수치는 main-header-metrics.json 참조.
- 생성 sheets/tools는 같은너비에서 높이2431로 실제와7px 차이. 시안의 질감·텍스트 렌더러·프리뷰내용/원위치는 생성 표현이며 앱의 라이브 프리뷰·선택폰트를 유지했다.
- 실제 카메라 시트는 스크롤 최대높이560dp 및 가용높이86%를 유지하므로 시안보다 첫화면에 보이는 하단 항목이 적다. 품질/비율/저장/보조 항목은 모두 스크롤에 있다. 시안에 그리지 않은 기능을 제거하지 않았다.
- 가이드 시안의 잘못된 보라/오렌지 색상과 새 +/-는 구현하지 않고 기존6색·숫자직접입력을 유지했다. 확대 시안의3/5/10x는 실제 지원장치에서만 노출되므로 고정1x QA기기에는1x만 표시한다.
- Expo Tools 회색 버블은 개발용 오버레이이며 앱 UI가 아니다. 원본 캡처에서 지우지 않았다. 광학줌/실제 토치/실기기 카메라 품질·Play 배포는 에뮬레이터 테스트 결과에 포함하지 않는다.
