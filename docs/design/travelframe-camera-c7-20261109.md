## 1. 기존 검증에서 확인된 사실

- C5 native device QA run [#42571836672](https://github.com/hebi10/travelframe/actions/runs/42571836672): 360/412/600/750dp 4개 Stage13 에뮬레이터 캡처 작업이 모두 **SUCCESS**. 각 프로필 PNG 99장/실패 0, 합계 396장. QA는 PR 테스트용 합성 기준 사진·오프라인 Android API35 기기에 한정.
- C5 기준 스냅샷 조합은 dark-100, light-130, dark-150, light-150 네 종류. 즉 **light-100과 dark-130이 빠져 있어** 24개 목표 조합을 충족하지 못함.
- C6 PR #145는 별도로 온보딩·카메라 권한·촬영 오류 안내를 변경. C6의 비공개 테스트 배포, ARM64 실사진 확인, Play 구독/백업 작업 완료를 가정하지 않음.

## 3. 화면 및 상태 검수

- 촬영: 프리뷰/헤더/셔터/촬영 설정·저장 위치·가이드·기준 사진 조정·색감·확대·조명·새 프로젝트.
- 기록: 프로젝트 목록, 상세(기록/수치/통계), 사진 상세, 전후 비교, 수치 관리, 알림·프로젝트 설정.
- 영상: 영상 홈/만들기/사진 선택/간격/화질/비율/텍스트 오버레이/보관함.
- 설정/계정: 화면·카메라 설정, 가이드 재실행, 가입/로그인 안내 등 기존 경로.
- 상태: 빈 기록, 첫 실행 온보딩(light/dark), C6 카메라 권한 거부와 고정 CTA, C5 색감 고정 저장·초기화.

## 4. 자동 검증 규칙

`scripts/verify-frame-journal-c7.py`:
1. 모든 캡처를 실제 Android PNG+UI XML+JSON 증거로 확인. 파일 누락, 잘못된 PNG 시그니처/치수, SHA-256 불일치·원본 `pixelEvidenceValid=false`는 FAIL.
2. 4개 프로필·6개 변형의 정확한 조합을 확인하고 공통 필수 화면이 빠지면 FAIL.
3. 카메라 색감 초기화/설정 저장, 최초 온보딩 시작/건너뛰기, 권한 거부 시 기록 이동의 **실제 클릭 가능한 네이티브 버튼 bounds**가 화면 안에 있는지 확인.
4. 설정 화면 좌측 여백의 **실제 PNG 픽셀 밝기**를 디코딩해 라이트는 밝고 다크는 어두운지 구분. 색상 라벨이나 추정 값만으로 통과하지 않음.
5. 각 QA 결과의 `sourceCommit`(PR 테스트 병합 SHA)와 `prHeadCommit`(실제 PR HEAD)을 기록하고, 네 프로필이 같은 코드에서 촬영됐는지 확인.
6. 실패 시에도 `c7-report.json`과 `c7-report.md`를 남김. 자동 PASS가 실제 인물 사진·TalkBack·렌더러/결제·운영 데이터까지 검증한다는 의미는 아님.

통합 Actions 작업 `c7-integrated-qa`는 네 프로필의 캡처 결과를 모아 24칸 매트릭스 전체를 다시 계산하며, 이 결과가 성공하기 전에는 C7 검증 완료를 선언할 수 없음.

## 5. 육안 검수 체크포인트

- 라이트/다크 색상 대비, 앱 화면과 카메라 위에 뜨는 다크 모달의 통일성
- 360dp 및 150% 글꼴의 버튼 잘림, 겹침, 불필요한 중첩 스크롤, 터치 영역
- 색감 패널은 초기화/설정 저장 고정, 가이드·기준 사진 확인/원본 제거 라벨의 구분
- 100/130/150%에서 첫 실행과 설정의 사용 가이드 다시 열기 분리
- 실기기 TalkBack 읽기 순서, OS에서 권한을 영구 거절한 경로, 하드웨어 카메라 재연결

**자동 검사 통과 후에도 PNG 원본과 실제 장치에서 수행할 육안 확인·수동 QA는 별도 게이트.**
