# TravelFrame C단계 — 온보딩·새 프로젝트 UI 정밀 보정
기준: 2026-11-07, main@ee768a761a7f6a88e1f6918c4880a28fc0eaf49f

## 최초 실행 온보딩
- 기존 `useAppGuide`의 첫 진입 판정(`shouldShowInitialAppGuide`)과 `markAppGuideIntroSeen` 저장 정책 유지.
- 카메라에 처음 진입하면서 가이드를 아직 보지 않은 경우(`replaySignal=0`, `body-frame-welcome`)에는 환영 안내를 다크·라이트 전체 화면으로 표시. 기존 카메라 비디오를 모달 뒤에 비치지 않고, 브랜드/진도 1/6, 큰 기본 일러스트, 안내, **시작하기** 및 **나중에 보기**로 구분.
- 기존 설정의 `사용 가이드` 재실행(`replaySignal>0`)에서는 소형 가이드 카드와 `다음`/스킵을 제공하여 첫 설치 온보딩과 반복 학습을 시각적으로 구별. 진행 단계의 기존 `AppGuideCard`와 step 상태/저장 구조 유지.
- 새로운 이미지·외부 의존성·애니메이션을 추가하지 않고 이미 사용 중인 `feature-capture.png`를 재사용.
- Safe Area, 화면 폭 360/412/600/750dp, 시스템 폰트 100/130/150%에서 스크롤·CTA 접근 가능 여부 확인.

## 새 프로젝트 생성
- 목표 100/365 표기에 '장' 단위를 명확히 표시. 실제 지원 플랜 제한과 직접 입력 가능 여부/상한, 생성 흐름은 변경 없음.
- `기준 사진`을 `촬영 기준 사진 방식`으로 명확히 하고, 두 번째 촬영 이후의 '최근 사진'/'첫 번째 사진' 설명을 간결하게 교정.
- 선택한 카드 배경/테두리 및 접근성 상태(라디오/힌트) 보강. 카드 최소 높이는 56dp로 유지, 안전 영역·키보드 대응·고정 생성 CTA 보존.
- 저장모델 `referenceMode`, 이름·목표 기록 수, 프로젝트 생성 제한/업그레이드·에러 처리/기존 프로젝트 데이터 불변.

## 검증
- Stage 13 기준 UI 기대/Stage 14 카드 높이 정적 테스트를 새 UI와 일치시키고 Stage C 단독 회귀 테스트 추가.
- Android 오프라인 합성 QA에서 첫 실행을 재현할 수 있도록 `intro_seen=False` fixture 모드 추가. 기존 사용자/설정 가이드 재실행은 기존 시나리오를 유지하면서 `다음` 라벨을 검증.
- 360/412/600/750dp의 캡처 매트릭스에 **실제 첫 실행 환영 화면**을 추가하여, 설정에서 연 가이드 화면과 분리해 두 가지 상태를 검증. 첫 실행 캡처는 테스트용 앱에서만 실행하고 실사용자의 저장소에는 접근하지 않음.
- 전체 TypeScript/ESLint/Node 테스트, Firebase Rules/Functions, Android Kotlin/Manifest, Secret Scan, Android x86_64 APK 및 네이티브 UI/캡처 PASS 후만 병합.
- ARM64 실제 기기, TalkBack 음성 흐름, 실사진·실계정 데이터는 계속 별도 미검증.
