# TravelFrame — C6 온보딩·권한·오류 안내 UI

기준: 2026-11-09 · Frame Journal / Android · C5 PR #144 후속 브랜치

## 목적과 변경 범위

- **최초 실행 온보딩**: 기존 환영 화면에 프로젝트 생성 → 첫 촬영 → 같은 구도로 기록의 3단계 시작 순서를 추가. 일러스트·상세 설명만 스크롤하고 `시작하기`·`나중에 보기`는 모달 하단에 고정. 최초 진입/가이드 재호출 구분과 단계별 `AppGuideCard`는 그대로 유지.
- **카메라 권한 미허용**: OS 권한을 요청해야 하는 이유, 카메라 없이 가능한 기록 탐색, 거절/재요청 불가 시 앱 설정으로 이동 안내를 구분. 설정한 라이트·다크 테마를 적용하고, 360dp 및 150% 글꼴에서도 `카메라 권한 허용` / `앱 설정에서 권한 허용`, `기록으로 이동` 버튼은 스크롤과 분리된 고정 푸터에 배치.
- **촬영 오류 안내**: 기존 한 줄 오류를 간결한 Frame Journal 안내 패널로 교체. 기본 닫기, 카메라 연결/촬영 시간 초과 시 **다시 연결**, 앨범 저장 권한 오류 시 **권한 설정** 동작을 상태에 맞게 노출. 자동 카메라 세션 복구 타이머가 있는 경우 수동 재연결 전에 취소하여 이중 재시작을 방지.
- **기존 앨범 권한 Alert**: `나중에` / `앱에만 저장` / `설정 열기` 분기 그대로 유지. Android 권한 요청 정책·저장 대상 선택 및 데이터 저장 코드를 수정하지 않음.

## 시각 규칙

- Frame Journal R0 팔레트: light `#F7F8FA / #FFFFFF / #181A1D`, dark `#0B0B0C / #1A1A1D / #F5F5F5` 등 기존 `useAppAppearance` 토큰 재사용.
- 44dp 터치, 주요 CTA 48dp 이상. 사진을 가리지 않도록 오류 패널을 촬영 컨트롤 영역에 한정하고 텍스트·아이콘·버튼 라벨로 상태를 구분.
- 추가 그림자·그라데이션·과도한 애니메이션·새 라이브러리 없음. 기존 일러스트 재사용. 신규 화면/탭/결제 플로우 없음.
- 카메라 프리뷰는 촬영 중 검정·차콜 그대로 유지. 권한 거절 안내는 사용자가 선택한 라이트/다크 모드에 반응.

## 검증

1. TypeScript/ESLint, 기존 Node 전체 회귀, C6 전용 TSX 파싱·버튼/권한 정책·복구 계약 테스트, Firebase Rules/Functions 및 Secret Scan.
2. Android Stage13에서 **실제 Android 권한 `pm revoke`** 후 `camera-permission-denied` 화면을 dark-100과 light-150 조건으로 캡처하고 Primary/Secondary 버튼의 화면 내 bounds 확인. `finally`로 카메라 권한 원상 복원. 테스트는 폐기 가능한 오프라인 에뮬레이터에서만 실행.
3. 최초 진입 `onboarding-first-run`, `onboarding-first-run-light-large` 및 설정 재실행 기존 캡처 확인. 360/412/600/750dp에서 푸터 잘림/설명 스크롤 확인.
4. **별도 수동 확인 필요**: `user-fixed`(권한 재요청 차단) 실제 OS 흐름, 카메라 하드웨어 장애·촬영 중 타임아웃 오류 배너, TalkBack 포커스·다중 창·접힌 화면, ARM64 실기기 및 카메라 재연결·앨범 저장.
5. CI 성공만으로 위 수동 동작의 정상 여부, 사용자 사진·Play 출시·Firebase 운영 반영 완료를 선언하지 않음.
