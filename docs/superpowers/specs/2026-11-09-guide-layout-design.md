# 사용 가이드 화면 정리

사용자 요청: 안내 화면을 자연스럽게 기획하고 수정한다. 촬영 탭은 Drive 기획서와 현재 구현을 비교한다.

## 선택한 방향

큰 브랜드 헤더를 축소하는 안과 중복 헤더를 없애는 안을 비교했다. 안내를 다시 보는 목적에 맞게 중복 헤더를 없애고 내용에 집중한다. 사용자가 디자인 판단과 수정을 위임했으므로 기존 앱의 토큰을 기준으로 진행한다.

- 재보기: 작은 `사용 가이드 / 1 / 6` 헤더, 짧은 제목, 실제 화면 이미지, 설명, 고정 탐색 영역 순서.
- `BODY FRAME`, 브랜드 설명, 중복 기능 칩은 재보기에서 제거한다. 첫 제목은 `몸의 변화를 기록하세요`로 줄인다.
- 나머지 다섯 제목도 기능을 짧게 표현하고 Android의 균형 줄바꿈을 사용한다. 상세 기능 설명은 유지한다.
- 스크롤되는 내용과 이전·다음·완료·닫기 버튼을 분리한다. 44dp 터치, 48dp 주요 버튼, 줄바꿈과 Safe Area를 유지한다.
- 이미 만든 PNG 7종과 3:2 비율을 유지한다. 새 이미지 생성, 전역 폰트/테마 변경은 필요하지 않다.
- 최초 방문은 기존 전체 화면·시작 순서·시작하기/나중에 보기를 보존한다. 가이드 버전 4와 진도 저장 정책도 보존한다.
- 촬영 탭은 별도 수정 요청이 없는 확인 작업이므로 기존 줌 수정·촬영 동작과 레이아웃을 건드리지 않는다.

## 검증과 보호 범위

기존 타입·린트·가이드 회귀, Pixel_9의 재보기 1~6단계, 작은 폭과 큰 글씨에서 스크롤·고정 버튼·이미지 표시를 확인한다. 실사용자의 저장소를 시딩하거나 사진/영상을 만들거나 삭제하지 않는다. 커밋·푸시·배포는 하지 않는다.

## 촬영 탭 기획 대조 결과

- Drive [화면별 UI/UX 검토](https://docs.google.com/document/d/1EEPCjSOLidZloCC2v561nW-W-rU0-BjLVXejztWl_Ps/edit?usp=drivesdk): 상단의 프로젝트·진행 정보를 간결히 묶고 셔터·갤러리·기준 사진 조작을 정렬한다. 첫 설치와 설정 재보기를 구분한다.
- Drive [Frame Journal R0 기준](https://docs.google.com/document/d/1msQm83e0g_YKp7c7LDgs2pX9moSanQc1jgd6wgWUh4M/edit?usp=drivesdk): 프리뷰 우선, 기존 4탭·촬영 동작 유지, 주요 조작 44dp 이상. 생성 시안은 실제 앱 구현 증거가 아니다.
- 로컬 `docs/design/travelframe-camera-c1-20261109.md`: 중앙 헤더 48dp·제목14sp·메타11sp, 별도 큰 카드 금지. C1~C7 관련 코드와 공식 회귀 7파일/36개는 존재하고 통과한다.
- 첨부 화면의 상단 박스는 이 간결한 헤더 의도와 차이가 있다. 구현은 `minHeight: 48`만 지정하며 제목·메타의 명시적인 행간이 없어 실측 확인이 필요하다. 병합 누락으로 단정하지 않는다.
- 검색과 관련 폴더 조회에서는 11월 9일 C1~C7의 별도 Drive 문서는 발견하지 못했다. Drive의 촬영 폴더에는 C0 Before ZIP 네 개가 있다. 이번 요청에서는 촬영 탭 코드를 변경하지 않는다.
