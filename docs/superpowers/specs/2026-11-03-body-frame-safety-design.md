# Body Frame 저장 안정성·화면 검증

## 승인 범위
2026-11-03 사용자는 앞선 전체 검토의 수정 순서(사진 보존 → 백업 → 영상 → 작은 화면·접근성 → 책임 분리)를 승인하고 모바일·태블릿 Android 에뮬레이터의 각 화면 캡처를 요청했다. 기존 Expo 55 / React Native / Firebase와 흑백 디자인을 유지한다.

## 목표
- 편집 파일 복사·미리보기·저장 정보 쓰기 실패에도 기존 사진과 목록 보존.
- 복원과 촬영·편집·삭제 경합에도 최신 목록 및 삭제 의도 보존.
- cloud_only 사진의 순서 변경은 파일 재업로드 없이 백업 정보에 반영.
- 만료 예약을 백업 한도에서 제외하고 중단된 음악 업로드도 전체 삭제 대상에 포함.
- 영상 수치는 immutable photoId로 연결하고 이미지 로딩 실패를 성공으로 처리하지 않음.
- 작은 화면·키보드·큰 글씨에서 첫 프로젝트 생성 가능, 사진·슬라이더에 접근 가능한 대체 조작 제공.
- 주요 탭과 하위 화면을 모바일·태블릿 에뮬레이터에서 실제 실행하여 캡처.

## 제약
- Android 전용. iOS 파일·설정은 수정하지 않는다.
- 기존 storage key, package ID, photoId와 프로젝트 데이터 형식을 유지한다.
- 사용자 사진·계정·운영 Firebase를 테스트 데이터로 사용하지 않는다.
- 운영 삭제·백업 슬롯 교체·Firebase 배포·스토어 배포는 실행하지 않는다.
- 새 의존성은 필요한 경우에만 추가한다. 기존 디자인 토큰과 색상을 사용한다.
- 미병합 PR72를 임의 병합하지 않는다.

## 구현 판단
기존 앱을 유지하며 변경 책임을 작은 helper로 분리한다. 전면 재작성은 기존 기록 마이그레이션 위험과 범위를 키우므로 선택하지 않는다. 서버·영상·UI는 독립 파일에서 구현하고 통합 검증한다. 로컬 저장·cloud client는 같은 작업자가 맡아 변경 큐 인터페이스를 일관되게 유지한다.

## 검증
원본 함수에 파일·저장 실패 및 동시 작업을 주입하는 실행형 회귀 테스트를 먼저 추가한다. 전체 Node suite, TypeScript, lint, Functions, Rules 검사를 수행한다. 모바일 360dp급과 태블릿 800dp급에서 주요 탭·프로젝트·사진·비교·측정·영상·설정·계정 화면을 촬영한다. 네이티브 모듈 또는 외부 서비스 검증 한계는 결과에 분리해 기록한다.
