# 광고·결제 출시 검증

## 수정 범위

광고 제거 권한 오류, 구독 변경 방식, 현재 변화 영상 저장 후 광고, UMP 동의 처리와 출시 문서를 보완한다. 상품 가격·프로젝트 한도·클라우드 결제 권한은 바꾸지 않는다. GitHub PR #56의 코드와 실제 운영 설정을 구분한다.

## 코드 정책

| 영역 | 처리 |
| --- | --- |
| 구매 상태 확인 중/실패 | 광고 요청 보류. 확인 실패를 이유로 클라우드 유료 권한을 부여하지 않음 |
| 캐시 오류 | 캐시 읽기·쓰기 실패와 서버 구매 검증을 분리 |
| 광고 제거 + 월 구독 | 서버에서 확인한 광고 제거 단품 권한을 별도 유지. 월 구독 만료가 단품 권한을 없애지 않음 |
| 구매 취소·환불 | 서버 검증 결과를 우선. 영구 캐시 신뢰 없음. 외부 환불 즉시 반영에는 RTDN과 앱 상태 갱신 검증 필요 |
| 구독 변경 | 상향·하향 모두 WITH_TIME_PRORATION. 기능·백업 한도 즉시 변경, 남은 금액을 기간으로 환산. 다음 갱신 시점으로 미루는 DEFERRED가 아님 |
| 광고 위치 | 현재 BodyFrameVideoScreen의 앨범 저장과 앱 보관함 저장 성공 이후. 실패 시 새 광고 요청 없음 |
| 전면 광고 | 앱 세션 내 최소 2분 간격, 로딩 대기 최대 3초, 동시 요청 제한. 화면 이탈·백그라운드·권한 변경 시 대기 요청 취소 |
| 광고 동의 | SDK의 UMP 결과 사용. 요청 가능 상태 이전에 Mobile Ads 초기화/광고 요청 보류. 개인정보 옵션 필요 시 설정 화면에 진입점 표시 |
| 비로그인 | 기존 showAds=false 정책 유지 |

## 자동 검증

새 테스트는 실제 소스를 TypeScript로 변환해 실행한다. Firebase·Play·AdMob·React Native의 외부 부분은 테스트 대역을 사용하므로, 실제 결제나 광고 송출의 성공 증거가 아니다. 저장 성공 순서, 결제 변경 요청 내용, 구매자 보호, 동의·화면 생명주기를 확인한다.

```bash
npm ci
npm run android:prebuild:ci
npm run quality
npm run release:verify
npm run quality:functions
npm run test:firebase-rules
```

네이티브 동의 설정과 R8 규칙이 추가되어 Android 개발/출시 빌드를 다시 만들어야 한다. JavaScript 업데이트만 배포하지 않는다. `release-post-save-ad-lifecycle`에는 prebuild로 생성된 Android 파일 검사도 포함된다.

## 내부 테스트 시나리오

아래 항목은 실행 증거를 기록하기 전까지 미확인이다.

- [ ] 무료 로그인 계정에서 테스트 배너/전면 광고를 확인하고, 광고 제거 구매 직후·재실행·재설치 복원 후 광고가 없는지 확인.
- [ ] 유효한 광고 제거 구매와 월 구독을 함께 보유한 계정에서 월 구독만 만료시켜 광고가 계속 차단되는지 확인.
- [ ] 연결 지연, 서버 구매 조회 실패, 기기 저장 오류에서 광고가 노출되지 않고 유료 클라우드 권한은 임의 부여되지 않는지 확인.
- [ ] Pro↔Plus↔Expert 여섯 방향 변경을 테스트하고, 확인 취소 시 Play 결제 화면과 성공 메시지가 나오지 않는지 확인.
- [ ] 상향·하향 시 Play가 제시하는 금액·결제일, 서버의 교체된 상품 권한, 클라우드 슬롯 제한이 일치하는지 확인.
- [ ] 취소 후 만료일까지 이용, 갱신, 환불/회수, RTDN 수신, 앱 구매 복원을 각각 확인. 다른 앱 계정으로 구매 복원을 시도하면 권한을 이전하지 않아야 함.
- [ ] UMP 테스트 지역에서 동의 필요/불필요/거절/오류와 개인정보 옵션 변경을 확인. 거절 후에도 수동 기록·영상 저장을 사용할 수 있어야 함.
- [ ] 영상 저장 성공/실패, 저장공간 한도, 광고 로딩 실패·지연, 화면 이동, 홈 버튼, 빠른 재생성에서 영상 파일과 저장 안내를 확인.
- [ ] 개발 중 실제 광고를 클릭하지 않고 테스트 광고 단위/테스트 기기를 사용.
- [ ] ARM64 실기기에서 촬영, 편집 저장, MP4 재생, 복원, Health Connect 거부/해제, 폴더블·큰 글꼴·작은 화면을 점검.

각 기록에는 검사 일시(KST), 커밋, 버전코드, 기기/Android 버전, 사용한 테스트 계정 유형, 결과와 증거를 남긴다. 구매 토큰·인증값·개인 사진·수치 원본은 문서나 공개 CI 로그에 올리지 않는다.

## 운영 확인

AdMob 앱 승인·스토어 연결·app-ads.txt·개인정보 메시지, Google Play 상품 활성화, Firebase Functions/Rules 배포와 Publisher API 권한·RTDN, 개인정보처리방침/계정 삭제 URL, Health Connect 신고와 데이터 보안 답변은 별도 운영 확인이 필요하다. 이번 코드 보완은 이 설정을 대신 완료하지 않는다.

2026-10-01의 npm 설치 로그에서 취약점 7건(중간 3, 높음 4)이 보고됐다. 영향 패키지와 실행 경로 분석 및 필요한 버전 갱신은 미완료이며, 강제 의존성 변경은 하지 않았다. 출시 승인 전 별도 확인한다.
